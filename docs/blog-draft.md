### 4.2 收藏联系人

**数据结构**：联系人上的一个布尔字段 `favorite`，跟着联系人一起存进 localStorage，不需要单独维护收藏列表。

**三个落点**：

1. 卡片右上角的星标按钮，点击切换 `favorite` 并立即重渲染；
2. 侧边栏「收藏联系人」视图，只筛 `favorite === true` 的联系人；
3. 排序时收藏置顶——在比较函数里第一优先级就是收藏状态：

```js
function sortList(list) {
  const collator = new Intl.Collator('zh-Hans-CN');
  return list.sort((a, b) => {
    const fav = Number(b.favorite) - Number(a.favorite); // 收藏的永远在前
    if (fav !== 0) return fav;
    if (state.sort === 'name')    return collator.compare(a.name, b.name);
    if (state.sort === 'company') return collator.compare(a.company || '\uffff', b.company || '\uffff');
    return String(b.updatedAt).localeCompare(String(a.updatedAt));
  });
}
```

**细节**：

- 星标按钮是卡片内的独立 `button`，事件用 `data-act="star"` 标记，点击时阻止冒泡到“点击卡片打开编辑”，避免误触；
- 收藏状态变化会同时更新侧边栏计数、统计卡片和卡片描边（`.card.is-fav` 用暖色描边 + 浅黄渐变区分）；
- 用 `Intl.Collator('zh-Hans-CN')` 排序，中文姓名按拼音而不是 UTF-16 码点排，`陈/林/苏` 的顺序才符合直觉。

### 4.3 一位联系人，多种联系方式

**类型**：手机、座机、邮箱、微信、QQ、地址、其他，共 7 种，定义在 `Store.METHOD_TYPES` 里，表单下拉框、卡片图标、导入映射三处共用同一份配置，加类型只改一处。

**表单**：默认给一行，点「添加一项」动态追加一行，每行是「类型下拉 + 值输入 + 删除按钮」；删到只剩一行时不允许再删空，保证表单始终有一个输入位。

```js
function addMethodRow(method) {
  const row = document.createElement('div');
  row.className = 'method-row';
  row.innerHTML = `
    <select class="method-type">${methodOptions(info.key)}</select>
    <input class="method-value" placeholder="${info.hint}">
    <button class="row-del">×</button>`;
  // 切换类型时同步更新 placeholder，删除时若只剩一行则不再删除
  ...
}
```

**校验**：按类型分派——

| 类型 | 规则 |
| --- | --- |
| 邮箱 | `^[^\s@]+@[^\s@]+\.[^\s@]+$` |
| 手机 / 座机 | 只允许数字、空格、`+`、`-`、括号，数字位数 5~20 |
| 其他 | 非空即可 |

校验失败时输入框标红、下方给出具体原因（例如“邮箱格式不正确：not-an-email”），并且不关闭弹窗，避免用户重填。

**展示**：卡片最多显示 3 条联系方式，多出来的用「还有 N 项联系方式」收口，保证卡片高度可控；电话和邮箱渲染成 `tel:` / `mailto:` 链接，手机上点一下就能拨号。

### 4.4 Excel 导出：手写一个 xlsx

作业要求“一位联系人一行、一类信息一列”，所以导出结构是固定的 12 列：

| 姓名 | 公司 | 职位 | 手机 | 座机 | 邮箱 | 微信 | QQ | 地址 | 其他 | 备注 | 是否收藏 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |

同一位联系人有多条同类型联系方式时，用中文分号 `；` 连接，例如两个手机号导出为 `138 0013 8000；139 0000 1111`。

**为什么不用 SheetJS**：课程作业要在离线/校内网打开，不能依赖 CDN；而通讯录只有一个工作表、只有字符串，自己写反而更可控。xlsx 本质是一个 ZIP 包，里面是若干 XML，于是拆成两步：

1. **生成 SpreadsheetML**：`[Content_Types].xml`、`_rels/.rels`、`xl/workbook.xml`、`xl/styles.xml`、`xl/worksheets/sheet1.xml`；
2. **打包成 ZIP**：只需要“存储模式”（method = 0，不压缩），自己实现 CRC32 和本地文件头/中央目录即可。

单元格全部用 `inlineStr` 内联字符串，而不是数字类型：

```xml
<c r="D2" s="2" t="inlineStr"><is><t xml:space="preserve">138 0013 8000</t></is></c>
```

这一条踩过坑：如果按数字写，Excel 会把 `13800138000` 显示成 `1.38E+10`，`0591-8888 6666` 这种座机还会被当成日期。全部按文本存，导出的号码和界面里一模一样。

样式上也做了处理，让导出的文件“能直接用”：表头深紫底白字加粗、首行冻结、自动筛选、按内容设置列宽。

核心的 ZIP 写入（省略了字段注释）：

```js
function zipStore(files) {
  let offset = 0;
  files.forEach(file => {
    const nameBytes = encoder.encode(file.name);
    const crc = crc32(file.data);
    // 本地文件头：PK\x03\x04 + 版本 + UTF-8 标志 + 存储模式 + 时间 + CRC + 长度 + 文件名
    const local = new Uint8Array(30 + nameBytes.length);
    ...
    // 中央目录项：PK\x01\x02 + ... + 本地头偏移
    offset += local.length + file.data.length;
  });
  // 末尾写 EOCD：PK\x05\x06 + 条目数 + 中央目录大小与偏移
}
```

文件名的 `0x0800`（UTF-8）标志位必须置上，否则中文文件名 `通讯录_20261116.xlsx` 在部分解压工具里会乱码。

### 4.5 Excel 导入：把表格读回通讯录

导入是导出的逆过程，但难点不在解压，而在“别人的表格格式不一定和你一样”。

**第一步：解包**。从文件末尾往前找 EOCD（`PK\x05\x06`），读出中央目录偏移与条目数；逐条读中央目录得到压缩方式、压缩后大小、本地头偏移；跳到本地头拿到真正的数据起点。压缩方式为 8（deflate）的条目交给浏览器原生的 `DecompressionStream`：

```js
async function inflateRaw(bytes) {
  const stream = new Blob([bytes]).stream()
    .pipeThrough(new DecompressionStream('deflate-raw'));
  return new Uint8Array(await new Response(stream).arrayBuffer());
}
```

这里用 `deflate-raw` 而不是 `deflate`，因为 ZIP 里存的是不带 zlib 头的原始 deflate 流。

**第二步：解析工作表**。`DOMParser` 解析 `sheet1.xml`，按 `r="D2"` 这样的单元格引用还原行列坐标；字符串可能在 `sharedStrings.xml`（`t="s"` + 索引），也可能是内联的（`t="inlineStr"`），两种都要处理——我们自己导出的文件是后者，Excel 另存的文件通常是前者。

**第三步：识别表头**。这是体验的关键。做法是给每个字段准备一组别名，先精确匹配、再包含匹配：

```js
const FIELD_RULES = [
  { key: 'name',    aliases: ['姓名', '名字', '名称', '联系人', 'name'], type: null },
  { key: 'mobile',  aliases: ['手机', '手机号', '手机号码', '电话', '联系电话'], type: 'mobile' },
  { key: 'tel',     aliases: ['座机', '固话', '办公电话'], type: 'tel' },
  { key: 'email',   aliases: ['邮箱', '电子邮箱', '邮件', 'email'], type: 'email' },
  ...
];
```

表头判断也有讲究：只有当第一行里有 ≥ 2 个单元格命中别名时才认为是表头，否则按“无表头”处理、用固定列序读取。早期版本只要命中一个别名就当表头，结果一行数据里出现“华为技术有限公司”就被误判成表头，整行丢失。

**第四步：去重与报错**。去重键是「姓名 + 第一条电话/邮箱」，比较前把空格、横线、括号都去掉，这样 `138 0013 8000` 和 `13800138000` 会被认成同一个号码。没有姓名、或一条联系方式都没有的行计入“格式异常”，在结果弹窗里提示到具体行号。

**结果反馈**：导入结束后弹窗给出三个数字（成功 / 重复跳过 / 格式异常）和逐条明细，而不是只弹一个 toast——用户需要知道“为什么只进来 2 条”。

### 4.6 数据存储与搜索

**存储**：`localStorage` 的 `ab.contacts.v1` 键，整个数组序列化成一个 JSON。选它的理由很简单：通讯录是单机小数据（每个联系人约 200 字节，5MB 能存两万多人），不需要后端；而且刷新、关浏览器都不丢。

读取时统一走一遍 `normalize()`：补 `id`、补时间戳、把 `methods` 里空值过滤掉、把非法类型归到“其他”。这样即使 localStorage 里是旧版本或被手改过的数据，页面也不会崩。

**搜索**：一个输入框同时搜姓名、公司、职位、备注和所有联系方式，大小写不敏感；号码额外做一次“去分隔符”比较，所以输入 `1380013` 也能搜到 `138 0013 8000`。搜索走 120ms 防抖，避免每敲一个字就整表重渲染。

**渲染**：列表用字符串模板拼 HTML，所有用户输入经 `esc()` 转义后再插入，防止姓名里带 `<script>` 造成注入。

### 4.7 页面样式与响应式

配色以靛蓝 `#4f46e5` 为主色，背景用两层径向渐变，卡片白底 + 1px 描边 + 大圆角，悬停时轻微上浮。所有颜色、圆角、阴影都收敛到 `:root` 变量里。

布局用 CSS Grid：桌面端是 `252px + 1fr` 的侧边栏 + 主区，卡片区 `repeat(auto-fill, minmax(302px, 1fr))` 自适应列数；窗口小于 980px 时侧边栏变成顶部一条，导航横向排列、卡片单列，表单两列变一列。

细节：

- 头像不用图片，用姓名生成渐变色 + 取中文最后一个字（“林晚晴”→“晴”），零资源加载也有辨识度；
- 弹窗用 `hidden` 属性控制显隐，配合一条 `[hidden]{display:none!important}` 兜底，避免组件自身的 `display:grid` 覆盖掉隐藏状态；
- 支持键盘：`Ctrl+K` 聚焦搜索、`Esc` 关闭弹窗、`Ctrl+Enter` 保存；
- 尊重 `prefers-reduced-motion`，关闭动画。

### 4.8 自动化验收

功能多了以后靠手点很容易漏，所以写了一个不依赖任何第三方库的端到端脚本：用 Node 自带的 WebSocket 直接连 Edge 的 DevTools 协议，真实点击、真实输入、真实下载文件。

`node tools/e2e.mjs` 会跑 21 项断言，当前全部通过：

```
✓ 首次打开为空列表          ✓ 载入 10 位示例联系人
✓ 星标收藏 +1               ✓ 收藏视图过滤正确
✓ 按公司搜索 / 按号码片段搜索 ✓ 新建联系人保留 3 条联系方式
✓ 缺姓名被拦截并提示         ✓ 编辑弹窗回填 3 条联系方式
✓ 删除后总数回到 10          ✓ 导出生成 xlsx 文件
✓ 导出文件回导全部判重       ✓ 外部 Excel 导入 2 位/跳过 1 位/异常 1 行
✓ CSV 导入（含引号内逗号）    ✓ 刷新后数据持久化
✓ 页面无脚本异常
```

导出的 xlsx 还会用 Python 的 `openpyxl` 再读一遍，确认表头、行数、冻结窗格、自动筛选都符合预期——这样能排除“自己写的解析器能读、但 Excel 打不开”的情况。

## 六、合作中的困难与解决

**1. 没有第三方库，Excel 怎么写？**

一开始想直接引 SheetJS，但作业要求离线可运行，CDN 方案被否掉。于是改成“读规范 + 手写”：先确认 xlsx 就是一个 ZIP 包，再对照 SpreadsheetML 写出最小的 6 个 XML 部件，最后用“存储模式”打包，避开 deflate 压缩。中间卡在 CRC32 和中央目录偏移上，导出的文件 Excel 报“文件已损坏”，用 Python 的 `zipfile` 逐条比对本地头和中央目录的字段后才定位到偏移量算错。

**2. 手机号导出后变成科学计数法**

第一版把数字写成 `<v>` 数值节点，Excel 里 `13800138000` 显示成 `1.38E+10`，座机号还会被识别成日期。改成全部用 `inlineStr` 文本节点，并在 `<t>` 上加 `xml:space="preserve"` 保留前后空格，问题解决。

**3. 导入别人的表格，表头五花八门**

有人写“手机”，有人写“手机号码”“联系电话”，还有直接给纯数据不带表头的。做了两级匹配（精确 → 包含）和“命中 ≥ 2 个才认表头”的保护，再保留按固定列序读取的兜底路径。

**4. 重复导入把通讯录搞成一堆重复项**

最初按姓名判重，结果同名不同人也被跳过。改成「姓名 + 第一条电话/邮箱」，并且比较前去掉空格和横线，既能拦住真正的重复，也不会误伤同名的人。

**5. 两个人并行改同一个文件**

`app.js` 一度是两个人都在改，冲突很难受。后来约定：数据层归黄和、交互层归周德斌，公共接口（`Store` 的方法名、联系人字段）先定后写，改动公共文件前先在群里说一声，冲突基本消失。

**6. 测试靠手点，改一处功能就漏一处**

功能加到导入导出后，每次改动都要把十几个流程手点一遍。于是补了 `tools/e2e.mjs`：用 21 条断言覆盖增删改查、收藏、搜索、导入导出、持久化，改完跑一遍，几十秒就能知道有没有回归。

## 八、总结与反思

这次作业最大的收获不是写完了三个功能，而是**先把接口定下来再动手**。联系人对象的字段、`Store` 的方法名在开工前就固定，两个人才能各写各的而不互相卡住；`methods` 用数组而不是定长字段这个决定，让“多联系方式”“导入导出”“卡片展示”三处都能复用同一份数据，后期加类型也不用改结构。

第二个收获是**“能跑”和“能验收”是两件事**。功能做完时觉得没问题，写了端到端脚本后才发现：导出再导入会把自己判成重复、手机号中间带空格时搜索搜不到、CSV 里引号内的逗号会把一行拆成两行。这些问题手工点一遍大概率发现不了。

不足的地方：

- 数据只存在 `localStorage`，换设备就没了，也没做多标签页同步；
- 导入没有做“预览确认”，大文件会直接写入；
- 云服务器部署（选做 15 分）这次没做，如果时间允许想用 Nginx 把静态资源挂上去，顺便验证一下跨域和缓存。

如果重做一次，会把 `app.js` 再拆细一点（渲染 / 表单 / 导入导出各一个文件），现在这个文件已经接近 700 行，虽然按区块注释分了段，但长期维护还是会累。
